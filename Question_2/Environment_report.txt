--------------------------------------------------
Command:

Output:

Observation:
The umask value of 0022 is subtracted from the maximum default permissions.
For directories, the base is 777; subtracting 022 leaves 755, which matches
exactly what was observed in the "before" permissions above. This confirms
umask is responsible for the default permission set on newly created
directories.

--------------------------------------------------
7. Explanation: How Permissions Protect Project Data
--------------------------------------------------
Linux permissions (read, write, execute for owner/group/others) enforce
access control directly at the filesystem level, independent of any
application-level security. By setting docs and logs to 700, only the owner
(veerd) can enter, read, or write to those directories — protecting
sensitive documentation and log files from any other user on the system,
even those in the same group. Setting src to 770 strikes a balance: it
allows trusted group members to collaborate on source code (read, write,
execute) while still blocking access to anyone outside the group. This
follows the principle of least privilege — each directory is given only the
access it actually needs, minimizing the risk of accidental modification,
data leakage, or unauthorized access to the project's files.
